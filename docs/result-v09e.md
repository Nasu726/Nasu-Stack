## Phase A — 私が入れた欠陥

### P1-01 テーマ初期化スクリプトへの差し込み

置き換え先が**引用符の中**にありました。

```js
var s=localStorage.getItem("__WT_STORAGE_KEY__");   // ← ここ
```

`storageKey` に `x");globalThis.x=1;//` を渡すと**データが実行コードになります。**

置き換え先を引用符の外へ出し、値を JS リテラルへ直列化しました。
逃がし処理は `lib/inline-script.ts` に 1 つだけ置き、JSON-LD と共有します。
`replaceAll` の置換文字列が `$&` を特殊扱いする件も、関数形にして塞ぎました。

**検査が、私が書いたばかりのそのファイルの欠陥を捕まえました。**
逃がし処理の `\u003c` が潰れていて、「`<` を `<` に置き換える」という
何もしない処理になっていました。**文字列を目で見て判断せず、実際に走らせる**
形にしていなければ通っていました。

### P1-02 guard を待っている間の中断

`AbortController` を guard の**後**に作っていました。

```
run() → guard を await → abort() → guard が true で解決
      → ここで初めて controller ができる → action 開始
```

**中断したはずの削除・決済・送信が、画面を離れた後に始まります。**

controller と世代番号を guard の前に作り、guard に `ctx` を渡し、
guard の throw を `ActionError` の経路へ乗せました。

わざと戻して赤を確認しています。

```
✗ guard を待っている間に中断したら action は動かない  (1 回)
```

カタログの題材は最初、**guard 自身が `signal` を見ていて**、部品が直って
いるのか guard が親切なだけなのか分かりませんでした。素朴な形に直しました。

### 途中で自分が壊したもの

「guard 中も pending」（P3-01）を入れたら、**確認ダイアログを閉じたあと
フォーカスがボタンへ戻らなくなりました**（`close()` の時点で既に body）。

アクセシビリティのほうが重いので、`pendingDuringGuard`（既定 true）を足し、
`ActionButton` は `confirm` があるときだけ切ります。遅い自前 guard では
今までどおり pending になります。**両方立ちます。**

## Phase C — 受け口

**継ぎ足すと読めなくなるので書き直しました。**

| | 直したもの |
|---|---|
| P1-03 | 応答の CORS だけでは副作用を止められない。`text/plain` の単純リクエストはプリフライト無しで届く。**攻撃者は応答を読めなくても、目的がメールを送らせることなら応答は要らない** |
| P2-04 | `ALLOWED_ORIGIN` 未設定が `*` へ逃げていた → 503 |
| P1-04 | `from` が固定で、書いてある通りに進めても Resend が 403 |
| P1-06 | `request.json()` が上限確認より先だった |
| P2-06 | 外部サービスの応答本文を丸ごとログに出していた |

判定は **「403 が返った」ではなく「メールが 0 回だった」**を見ます。
わざと戻すと赤くなります。

```
✗ 違う送信元 + text/plain でもメールは送らない  (1 回)
```

レート制限・Turnstile・Idempotency-Key は v1.x。README に「入っているか」の
表を置き、レート制限は Cloudflare の画面での手順を書きました。
