## 計画から変えた判断

### 狭い画面のメニューを `<dialog>` から `<details>` へ

計画では「`ConfirmDialog` が使っている `<dialog>` を使い回す」つもりでした。
作る途中で、これでは要件を満たせないと分かりました。

`<dialog>` を開くには JavaScript が要ります。Astro のヘッダを島にした場合、
**JS が届くまでハンバーガーは押しても何も起きません。** 回線が遅いほど長くなります。

`<details>` はブラウザ自身の機能です。

| | `<details>` | `useState` で自作 |
|---|---|---|
| JS 無しで開閉 | ○ | × |
| キーボード（Enter / Space） | ○ | 自分で書く |
| 読み上げの開閉状態 | ○ | 自分で書く |
| Ctrl+F が閉じた中身を見つける | ○ | × |
| Astro で `client:` が要る | 要らない | 要る |

**JavaScript を切ったブラウザで実測し、メニューが開くことを確かめました。**

Esc で閉じる処理だけ JS で足していますが、無くてももう一度押せば閉じます。
これが正しい足し方の順序です（`Dialog` 自体は作ってあり、
中央モーダルと端から出るシートの両方に使えます）。

## 見つけて直したもの

### 1. Esc で閉じるとフォーカスが body へ落ちていた（本物のバグ）

`DropdownMenu` は項目を選んだときと Tab のときは開いたボタンへ戻していましたが、
**Esc のときだけ戻していませんでした。** キーボードだけの人は、閉じるたびに
ページの先頭から辿り直しになります。

`usePopover` が「なぜ閉じたか」を渡すようにしました。

```ts
export type CloseReason = "escape" | "outside";
```

Esc なら戻す、外側を押したなら戻さない（押した先からフォーカスを奪わない）。
理由を渡さない設計だと、この 2 つを区別できません。

### 2. `role` を正しくしたら、既存の検査が壊れた

`verify-states.mjs` は `getByRole("button", { name: "状態" })` でタブを押していました。
タブを `role="tab"` にした瞬間、見つからなくなって落ちました。

**壊れたのは正しさの証拠です。** 検査側を URL 指定（`?tab=`）へ寄せました。
ついでに `verify-layout.mjs` も共通の起動処理に寄せています。

## 検査の誤りを 6 つ直しました

作ったものより、**測り方の間違いのほうが多かった**回です。

| 誤り | 何が間違っていたか |
|---|---|
| 背面スクロール | `window.scrollBy` で測っていた。あれはプログラム操作なので `overflow: hidden` でも動く。ホイール入力で測り直したら止まっていた |
| フォーカストラップ | `activeElement` が body になるのを「外へ出た」と数えていた（12 回中 3 回）。Chrome はモーダルの端でブラウザ UI へ移り、そのとき body になる。背面は inert なので、**ページ内の要素を掴まないこと**を見るのが正しい。数え直したら 0 |
| タブの横スクロール | 1200px で測っていたので入りきっていた。380px にしたら期待どおり |
| summary の高さ | `.wt-summary` の 1 つ目はヘッダのハンバーガーで、広い画面では高さ 0。`.wt-disclosure > .wt-summary` に変更 |
| 見出しの余白 | 先頭の `h2` で測っていた。そこは 0 が正しい（`:first-child` は 0 にしている）。`h3` で測り直し |
| 本文中のリンク | 高さ 19px を「タップ領域が小さい」と叱っていた。**WCAG 2.1 の 2.5.8 には「インライン」の例外**があり、文中のリンクは対象外。行間を広げて直すのは本文を読みにくくするだけ |

最後のひとつは、検査が**直しようのない指摘を出し続ける**類のものでした。
そういう指摘があると、本物の指摘まで無視されるようになります。
