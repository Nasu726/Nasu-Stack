## 2. 端末幅の実測結果

`scripts/audit-responsive.mjs` と `scripts/audit-stress.mjs` を書いて、
320 / 375 / 414 / 768 / 1024px で機械的に調べました。

### 効いているもの（レイアウト部品の成果）

現状のカタログと Astro サイトは、**どの幅でも横スクロールが出ません**。
`Columns` の自動畳み、`Inline` の折り返し、`Tiles` の列数切替が想定どおり効いています。

「壊しにくる中身」を入れた試験でも、次は耐えました。

```
✓ 実寸の大きい画像（1600x900）
✓ 列の多い表（9 列）
✓ Column に固定幅 18rem（畳んだ状態）
✓ Tiles に 4 列を強制
✓ Inline に長いタグを大量に
```

### 壊れるもの

```
✗ 折り返せない長い URL        320px で 577px はみ出し
✗ 長い英単語の羅列            320px で 349px はみ出し
✗ 長い行を含むコードブロック   320px で 637px はみ出し
```

**原因は共通で「折り返せないテキスト」です。** レイアウト部品は正しく縮んでいるのに、
中身のテキストが縮まないので、そこから外へ突き抜けます。
実際のサイトでスマホ表示が壊れる原因の大半がこれです。

### そのほかの指摘

| 指摘 | 件数 | 何が起きるか |
|---|---|---|
| **入力欄の font-size が 16px 未満** | 全 7 箇所 | iOS が入力欄に触れた瞬間に画面を自動拡大する。戻すのは手動 |
| **タップ領域が 24px 未満** | Astro サイトのナビ 2 件 | 指で押しづらい。WCAG 2.1 AA の最低基準を下回る |
| 本文の 1 行が長すぎる | 768px 以上で 6 件 | 読みにくい |

`Field` の入力欄が 14px なので、**このテンプレートで作ったフォームは全部
iOS で拡大されます**。初心者が自力で気づける類のものではありません。

## 3. v0.3 でやること

### A. 壊れない土台（最優先）

テキストのはみ出しを、部品側で構造的に防ぎます。
利用者が `overflow-wrap` を知らなくても壊れない状態にします。

- 長い文字列の折り返しを既定にする（`overflow-wrap: anywhere`）
- `pre` / `code` は横スクロールに閉じ込める
- `img` / `video` / `svg` / `iframe` を親幅に収める
- flex/grid の子が縮めるよう `min-width: 0` を徹底

### B. 端末固有の落とし穴

- **`Field` の入力欄を 16px 以上に**（iOS の自動拡大を止める）
- 触れる要素の最低タップ領域を保証する（`Button` の `sm` を含む）
- `Section` / `PageBlock` の余白をスマホで詰める既定値

### C. 表とスクロール — `Scrollable`

狭い画面で表を潰すのではなく、**その部分だけ横スクロールさせる**部品。
端が切れていることが分かる影も出します。
`DataTable` を作る前にこれが要ります（順番を逆にすると作り直しになる）。

### D. 崩れを検出できるようにする ← 差別化の本体

今回書いた 2 本の監査スクリプトを、利用者が**自分のサイトに対して**
回せる形で同梱します。

```bash
npm run check
```

> 320px: 横に 577px はみ出し
>   ↳ `<p class="...">https://example.com/very/long/...`
> 入力欄の font-size が 16px 未満: 3 件 → iOS で自動拡大されます

「スマホで崩れてないか」を**目視ではなく数値で**確かめられます。
既存のテンプレート・ブロック集にこれは付いていません。

### E. カタログに端末プレビュー

幅を 320 / 375 / 768 / 1024 に切り替えるボタンを置いて、
その場で崩れを確認できるようにします。

## 5. なぜ部品を増やすより先に端末幅なのか

1. **実際に壊れている。** 推測ではなく実測で 3 ケース + 7 箇所の指摘が出ている
2. **`DataTable` を作る前に「狭い画面で表をどうするか」の答えが要る。**
   先に部品を作ると、後で全部作り直しになる
3. **今なら安い。** 部品が 6 個の今のうちに土台を直せば全部に効く。
   20 個になってからでは全部を見直すことになる
4. **検出できることが差別化になる。** 「崩れない」は主張だが、
   「崩れていないことを数値で示せる」は証明
