# 責任分界

**Nasu Stack は「初心者を困らせない、ベテランを縛らない」ための土台です。**
Web 開発で繰り返す判断を、安全な既定値・明示的な制約・小さな primitive に変えます。
アプリケーションに必要な判断を、すべて代行するものではありません。

この文書は、Nasu Stack の責任がどこまでかを示す公開仕様です。
機能を提案するとき、最初に問うのは次のことです。

> これは誰が決めるべきことで、Nasu Stack はどこで決めるのをやめるべきか。

*[English](boundaries.md)*

## 4 つの原則

1. **安全な既定値。** 初めて触る人が、原因を特定できない失敗に最初の道で
   出会わないようにします。
2. **明示的な境界。** ブラウザ側の便利機能を、サーバ側の保証として説明しません。
3. **エスケープハッチ。** 既定値は案内であって、檻ではありません。コンポーネントから
   hook へ、hook から素の React やブラウザ API へ降りられます。
4. **再利用できる primitive または契約。** 繰り返す配線は引き受けますが、
   アプリケーション固有の業務判断は引き受けません。

4 つは対です。エスケープハッチのない安全な既定値は利用者を縛り、
安全な既定値のないエスケープハッチは、初心者に同じ失敗を再発見させます。

## 誰が何を決めるか

| 領域 | Nasu Stack が引き受ける | アプリ／ドメインが引き受ける | サーバ／基盤が引き受ける |
|---|---|---|---|
| 配布するソース | 各レジストリアイテムの文書化した挙動・型・依存・検査 | どのアイテムをコピーし、どう組み合わせ、コピー後に何を変えるか | 配備と実行環境の互換性 |
| レイアウトとアクセシビリティ | レスポンシブな既定値と、部品内部の意味・フォーカス・キーボード・読み上げ | 内容・ラベル・ページ全体の見出し順と、組み合わせが目的に合うか | 環境固有の描画や支援技術に関する方針 |
| 非同期の画面状態 | 読込中・成功・失敗、二重送信の防止、中断信号、取り消した／古い結果を画面へ戻さないこと | 成功の意味、表示する文言、中断を利用者に提供するか | 処理を実際に中断・巻き戻しできるか、原子的に確定するか |
| 入力とデータ | ブラウザ側の助言と、Nasu Stack 自身の公開契約に対する実行時検査 | ドメイン規則と、API に期待するデータ形 | 認証・認可・正規の入力検証・CSRF 対策・レスポンス schema |
| JSON 通信 | 空の成功応答を空として扱い、JSON media type を受け入れ、不正／非 JSON の本文を fail closed にすること | parse 後の値をドメイン型へ変換すること、または別の通信手段を選ぶこと | 正しい status・media type・本文と、安全なエラー応答 |
| リトライ | 上限のある仕組みと、不正な retry policy を制御された失敗にすること | 同じ操作を繰り返して安全な場合だけ有効にする判断 | 冪等性・重複排除・transaction・rate limit |
| アップロード | 選んだファイルに対する、その場のブラウザ側フィードバック | プロダクト固有の上限と、受理／拒否後の体験 | 大きさ・種類・magic bytes・malware・保存・認可の検査 |
| 受け口の見本 | fail closed な小さな結合例と、制限の明記 | アプリの項目や利用サービスに合わせた変更 | 本番の認証・認可・rate limit・bot 対策・log・秘密管理 |

Nasu Stack が責任を持つのは、配布時点のレジストリソースです。shadcn はソースを
利用者のリポジトリへコピーするため、**変更したコピーは利用者のアプリに属します。**
何を変えても構いませんが、変更後の挙動は元アイテムの保証範囲から外れます。

## 契約が意味すること

### 中断は古い画面更新を防ぐが、サーバ処理を巻き戻さない

`Action` は `AbortSignal` を受け取ります。Nasu Stack が中断を管理する場面では
signal を abort し、既に取り消された／後の操作に置き換わった結果を画面へ反映しません。

これは、通信が止まった証明でも、データベース更新・メール送信・決済を取り消す機能でも
ありません。その意味はサーバ側で実装します。abort は「止めてほしい」という要求であり、
「何も起きなかった」という証明ではありません。

### `jsonRequest` が検証するのは通信形式であり、ドメインではない

`jsonRequest` は空の `204`・`205`・成功応答を `undefined` として受け取ります。
本文がある成功応答は `application/json` または `application/*+json` の media type と
正しい JSON が必要で、それ以外は `BAD_RESPONSE` として fail closed にします。

JSON として parse できても、アプリが期待する object だとは限りません。信頼できない
応答値は、ドメインの入口で検証してください。意図して text を返す endpoint には、
`fetch` または用途専用の helper を使います。

### ブラウザの入力検証はフィードバックであり、正規の判定ではない

Field・`FileDrop`・form helper は、その場で誤りを伝え、誤送信を減らせます。
呼び出す側はすべてを迂回できます。全ての値と権限について、最終判断はサーバ側です。

### リトライには冪等性の判断が要る

`retry` は、同じ要求を繰り返して安全な操作にだけ有効にします。
決済・注文作成・メール送信は通常これに当たりません。応答だけ失われ、最初の要求が
既にサーバへ届いていることがあります。

そのような操作を再試行する必要があるなら、`Idempotency-Key` など、同じ要求を 1 回と
扱うサーバ側の仕組みと対で設計します。クライアント側からその保証は推測できません。

### アクセシビリティは組み合わせる側とも共有する

Nasu Stack は、配布する部品内部の意味と操作を引き受けます。正確なラベルの選択、
ページ全体の見出し階層の修復、内容の順序が意図を表すかの判断はできません。
部品が用意するアクセシブルな道を、アプリ側でも組み合わせや変更の際に保ちます。

必要な意味とキーボード操作をブラウザが既に持つなら、Nasu Stack はそれを模倣せず、
native control を土台にします。また、既定 timer が過ぎたという理由だけで操作を
取り上げません。action 付き Toast は、アプリが `duration` を明示しない限り
自動で閉じる timer を持ちません。ただし、明示的な dismiss / clear や Provider の
`max` を超えたときの押し出しでは閉じます。文言・時間制限・queue 数はアプリ側の判断です。

## 誤解しやすい便利機能

### `FileDrop` の `accept` と `maxSize`

**守りではありません。** 見ているのはファイル名の末尾と、ブラウザが推測した種類です。
どちらも送る側が決められるため、`virus.exe` を `photo.png` に変えるだけで通り得ます。

ブラウザ側の検査は、間違ったファイルを選んだ人へその場で伝えるためにあります。
受け取るサーバ側で大きさ・種類・実際の magic bytes を検査してください。
画像なら SVG も実際の形式として扱います。

### `HoneypotField`

単純な bot の送信を減らします。認証・認可・CSRF 対策・rate limit・専用の bot 対策の
代わりにはなりません。

### `EndpointSpec.defaults`

クライアントが送る値なので、同じ key が入力にあれば入力が勝ちます。
`role`・`tenantId`・`userId` のような認可用の値を置かないでください。
本人性と権限はサーバ側で決めます。

### ブラウザの header と環境変数

`EndpointSpec.headers`・`createSubmit({ headers })`・
`uploadWithProgress(..., { headers })` はブラウザから送られます。

```ts
// これは秘密になりません
headers: { Authorization: `Bearer ${SERVICE_API_KEY}` }
```

開発者ツール・通信 log・ブラウザ拡張から読めます。`PUBLIC_` または `VITE_` で始まる
環境変数もブラウザへ配られます。他のサービスを秘密の値で呼ぶ必要がある場合は、
自分が管理するサーバを間に置き、そこから呼び出します。

## 秘密をどこに置くか

| 置き場所 | 誰が読めるか | 置いてよいもの |
|---|---|---|
| `PUBLIC_*` / `VITE_*` の環境変数 | **誰でも** | 公開してよい URL と公開鍵 |
| ブラウザから送る header | **誰でも** | 公開してよい token |
| ブラウザ用コードに直接書く | **誰でも** | 秘密は何も置かない |
| サーバ側の秘密管理 | 認可された運用者と service | API key・送信先・認証用の鍵 |

迷ったら「この値を公開ページに印字できるか」で判断します。
できないならブラウザへ置いてはいけません。

## Nasu Stack が提供しないもの

- 認証・認可システム
- database・ORM・transaction manager・サーバ側 application framework
- 正規のサーバ側入力検証やドメイン schema
- CSRF 対策・rate limit・bot 対策・アップロード内容検査
- ブラウザ操作の中断がサーバ側の副作用を巻き戻すという保証
- コピーしたソースを変更した後も、アプリがアクセシブル／安全であり続けるという保証

これらに関する primitive や結合例を提供することはあります。それによって本番運用の
責任が Nasu Stack へ移るわけではありません。脆弱性の報告方法と、セキュリティ上の
より狭い保証範囲は [`../SECURITY.md`](../SECURITY.md) にあります。
