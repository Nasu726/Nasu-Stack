## 部品が 2 か所にならないようにした

テンプレートに部品をコピーして commit すると、原本と合わせて 2 か所になります。
**このリポジトリが何度も壊れた原因そのもの**です。

- ヘッダの高さが 2 か所 → アンカーが 64px 隠れた
- タブの一覧が 3 か所 → 新しい画面が 320px で一度も検査されていなかった
- 下書きの除外が 3 か所 → 漏れても自分の文章なので気づけない
- 入力欄の class が 4 か所 → テーマを変えると 1 つだけ違う見た目に

だからテンプレートは `scripts/build-create-template.mjs` の**生成物**にして、
`.gitignore` に入れました。手で編集する余地が無ければ、ずれようがありません。
検査でも「原本とテンプレートの中身が一致する」を見ています。

## 「生成できた」では足りない

生成物が本当に動くかを機械で確かめます。

```
✓ 8. astro: pnpm install が通る      ✓ 8. vite: pnpm install が通る
✓ 9. astro: 型検査が通る             ✓ 9. vite: 型検査が通る
✓ 10. astro: ビルドが通る            ✓ 10. vite: ビルドが通る
✓ 11. astro: 配信して画面が出る       ✓ 11. vite: 配信して画面が出る
✓ 12. astro: 端末幅の検査（5 幅）を通る ✓ 12. vite: 端末幅の検査（5 幅）を通る
✓     astro: 画像が場所を取っている    ✓     vite: 画像が場所を取っている
```

install と build は時間がかかるので `pnpm verify:create` に分けています。
**ただし手動確認ではなく、機械で回します。**

そのほかの判定（`pnpm verify` に入る軽い側）:

```
✓ 0. テンプレートが生成できる  (astro 39 / vite 42)
✓    原本とテンプレートの中身が一致する
✓ 3. 必要なファイルが揃っている  (41 ファイル)
✓ 4. 空でないディレクトリには生成しない  (終了コード 2)
✓    もとのファイルが残っている
✓ 5. 空のディレクトリになら生成できる
✓ 6. 不正な名前を弾く（大文字 / 空白 / 先頭のドット / 空 / スラッシュ）
✓ 7. tsconfig の paths が src/* を指す
```

**4 が一番大事です。** create 系の道具で一番やってはいけない事故は、
既存のディレクトリを上書きすることなので。

## 見つけて直したもの（既存変更 3 件・報告）

### 1. 足場のコードが型検査に通らなかった

```
src/App.tsx(43,19): error TS2322:
  Property 'action' does not exist on type 'ButtonProps'
```

`Button` に `action` を渡していました。それは `ActionButton` です。
用途で分けてあるのに、自分で取り違えました。

**`vite build` は通ります。** 型検査だけが落ちます。
生成物の `npm run build` を `tsc --noEmit && vite build` にしておいたので
利用者は気づけますが、**雛型が壊れたコードを配るところでした。**

### 2. `SiteHeader` が、幅のある `actions` ではみ出す

生成した Vite 版に `ThemeSwitcher` を置いたら、375px で 15px はみ出しました。

```
横に 15px はみ出しています
  ↳ <details class="md:hidden"> が 15px 外へ
```

原因はヘッダの行が縮めないこと。**flex の子は既定で `min-width: auto`** なので、
中身より小さくなれません。幅のある `actions` を渡された瞬間に突き抜けます。
`min-w-0` を追加しました。

### 3. `ThemeSwitcher` が 320px で折り返せない

2 を直したら、今度は 320px で `ThemeSwitcher` 自身が突き抜けました。
中のボタン群（4 テーマ）が `flex` のまま `min-w-0` を持っていませんでした。

**2 と 3 は同じ原因です。** flex の子は既定で縮まない——
`Inline`（v0.3）・表（v0.5）・ヘッダ（今回）で、**3 回目**の遭遇でした。
`docs/overview.md` の「踏んだ失敗から決めた規則」に入れてあります。

### レジストリの不整合 1 件

`prose.css` だけ `target` が `lib/prose.css` を指していました
（`tokens.css` と `themes.css` は `styles/`）。`styles/prose.css` に揃えました。
生成物のディレクトリ構成を組み立てて初めて気づきました。
