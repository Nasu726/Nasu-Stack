## 直したもの

### A-2. 「v0.8 の宿題です」→ もう配線済みだった

### A-3. 「ブログの連絡先からも」→ ブログに連絡先は無い

存在しない導線を案内していました。一文を落としました。

### A-4. 検査コマンドの例が、そのままでは打てない形

`npm run check -- http://localhost:5173` は URL が 2 つ渡ります
（雛型の `check` は URL を埋め込んであります）。
`npm run check` に直し、astro なら 4321 / vite なら 4173 だと書き添えました。

### A-5. 「250ms」と「350ms」が同じ画面に出ていた

前者は部品の既定の debounce、後者はデモが偽の通信に入れた待ち時間。
hint を「応答に 350ms かかる想定にしてあります」に変えました。

### C-3. `fail` が「部品の仕様」に見えていた

作者の指摘どおり、**これはこのデモの偽サーバーの挙動**で、
部品の仕様ではありません。区別が付かないと
「たまたま fail という文字列が入ったファイルも失敗するのか」という
不安に繋がります。

説明文と入力欄の重複を消したうえで、

> **このデモの偽サーバーは、名前に `fail` を含むファイルだけ拒否します。**
> 部品の仕様ではありません。

と明記しました（FileDrop と useOptimisticList の両方）。

作者の案。**両方書けば、初心者にもベテランにも通じます。**
