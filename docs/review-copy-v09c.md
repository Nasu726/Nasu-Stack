## A. 事実と違う／古い

### A-1. 「Ctrl+F が閉じた `<details>` の中も見つける」— ブラウザによります

| | |
|---|---|
| 場所 | `apps/playground/src/NavDemo.tsx`（Disclosure の説明）／ `registry/nasu/components/ui/site-nav.tsx`（doc コメント） |
| いま | 「Ctrl+F のページ内検索が閉じた中身も見つけてくれるのも、自前で作ると失うものです」 |

閉じた `<details>` を検索で開く挙動は、**Chrome 系では動きますが、
すべてのブラウザで保証されているものではありません。**
「自前で作ると失う」と言い切ると、失っていない環境の人に嘘になります。

**この点は裏が取れていません**（手元にオフラインの資料しかありません）。
採用するなら、まず現在の対応状況を確認してから文言を決めてください。

> 直す案: 「Chrome ではページ内検索が閉じた中身も見つけます（対応はブラウザによります）」

### A-2. 「v0.8 の宿題です」— もう終わっています

| | |
|---|---|
| 場所 | `apps/site/src/pages/contact.astro` 冒頭のコメント |
| いま | 「**送信先はまだ配線していません。**「で、どこに送るの？」は v0.8 の宿題です。いまは ContactForm の中で偽の API を呼んでいます」 |

`ContactForm.tsx` は `PUBLIC_CONTACT_ENDPOINT` を読んで実際に送る形になっており、
未設定のときだけ偽物に落ちます。**コメントのほうが古いままです。**

> 直す案: 「送信先は `PUBLIC_CONTACT_ENDPOINT` で外から渡します。未設定のときだけ、送らずに成功したふりをします」

### A-3. 「ブログの連絡先からも」— ブログに連絡先はありません

| | |
|---|---|
| 場所 | `apps/site/src/pages/contact.astro` 本文 |
| いま | 「送信できないときは、ブログの連絡先からもご連絡いただけます」 |

リンク先の `/blog/` に連絡先はありません。**存在しない導線を案内しています。**

> 直す案: この一文を消す。または「送信できないときは、しばらく置いてからもう一度お試しください」

### A-4. 検査コマンドの例が、実際には打てない形

| | |
|---|---|
| 場所 | `apps/playground/src/ResponsiveDemo.tsx`（崩れていないことを数値で確かめる） |
| いま | `npm run check -- http://localhost:5173` |

生成される雛型の `check` は、URL を**スクリプト側に埋め込んであります**
（astro なら `4321`、vite なら `4173`）。
この例のとおり打つと URL が 2 つ渡り、**動いていないほうを見に行って失敗します。**
ポート `5173` も、雛型のどちらにも一致しません。

> 直す案: `npm run check`（URL は package.json に書いてあります）

### A-5. AsyncSelect の「250ms」と「350ms」が同じ画面に出ています

| | |
|---|---|
| 場所 | `apps/playground/src/PartsDemo.tsx`（AsyncSelect） |
| いま | 説明「250ms の debounce を入れ」／入力欄の hint「350ms の遅延を入れてあります」 |

前者は部品の既定値、後者はこのデモが**偽の通信にわざと入れた待ち時間**で、
別のものです。並ぶと矛盾に見えます。

> 直す案: hint を「応答に 350ms かかる想定にしてあります」に変える

## C. 説明の量・置き場所

### C-1. 「まだ作っていません」の文面が、開発者向けです

| | |
|---|---|
| 場所 | `apps/playground/src/App.tsx` の `NotBuilt` |
| いま | 「tabs.mjs にはありますが、App.tsx の PANELS に対応する中身がありません」 |

**カタログを見に来た人に、こちらの内部のファイル名は意味がありません。**
（開発中に気づくための表示なので、残す判断も十分あり得ます。）

> 直す案: 画面には「この章はまだ準備中です」とだけ出し、詳細は `console.warn` へ

### C-2. `ActionProvider` が「レイアウト」タブにあります

| | |
|---|---|
| 場所 | `apps/playground/src/LayoutDemo.tsx` の `ToastDemo` |

余白と段組の章に、エラー処理の受け皿の話が混ざっています。
**「状態」タブのほうが探しやすいはずです。**

> 直す案: `ToastDemo` を `App.tsx` の `state` パネルへ移す

### C-3. 「fail を入れると失敗します」が 2 回ずつ出ます

| | |
|---|---|
| 場所 | `PartsDemo.tsx`（FileDrop）／ `FormsDemo.tsx`（useOptimisticList） |

> 直す案: 手元で操作する人が見るのは入力欄のほうなので、**説明文側から消す**

### C-4. 「トンマナ」

| | |
|---|---|
| 場所 | `apps/playground/src/App.tsx` の導入文 |
| いま | 「上のスイッチでトンマナを切り替えると」 |

### C-5. デモサイトの記事が「検査用です」と自己申告しています

| | |
|---|---|
| 場所 | `apps/site/src/content/blog/qa.md` / `draft-note.md` |

### C-6. 会社概要の「2 営業日以内にお返事します」
