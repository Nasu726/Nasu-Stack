## 「既存に触らない」の結果

今回の制約は「新しいものは新しいファイルとして足す。既存の部品を直さないと
雛型が作れないなら、それは部品の設計が足りていない合図」でした。

**1 件だけ、既存の部品に手を入れました。** 報告します。

### `SiteHeader` に `brandHref` を足しました（26 行の追加）

ブログのページでブランド名をホームへのリンクにしようとして、こう書きました。

```astro
<SiteHeader brand={<a href="/">{SITE.name}</a>} ... />
```

ビルドが落ちました。

```
Expected ">" but found "href"
  Location: src/pages/blog/index.astro:42:314
```

**`.astro` のファイルでは、props に要素を書けません。** Astro のテンプレートは
JSX に似ていますが、属性の位置に要素を置く構文がありません。

`brand` の型を `React.ReactNode` にしていたのは、React 側の使い勝手だけを見た設計でした。
Astro の island に渡せるのは JSON になる値だけ——これは v0.2 で `ActionSpec` を
足したときに学んだはずの制約で、**同じ穴をもう一度踏んでいます。**

行き先だけを文字列で受け取る `brandHref` を足しました。
`brand` は今までどおり動きます（既存の呼び出しは 1 つも変えていません）。

この 1 件を除き、`registry/` に足したのは新しいファイル 2 つ（`lib/seo.ts` /
`lib/feed.ts`）だけです。

## 実測

### 純粋な関数の単体検査（36 件、ブラウザ不要）

ブラウザを立てないので速く、**`&` ひとつでフィードが壊れる類の間違いは
ここでしか捕まえられません。**

書いている途中で 1 つ穴を見つけました。

**JSON-LD の中の `<` を逃がしていませんでした。**

```
記事名: 危険な</script><img src=x>タイトル
```

JSON-LD は `<script>` の中に素で書き出すので、記事名に `</script>` が入っていると
**そこでスクリプトが終わり、残りが本文として描画されます。** 差し込みの穴にもなります。
`JSON.stringify` は `<` を逃がしてくれないので、自分で `<` にする必要があります。

```js
must("JSON-LD の中で < を逃がしている（</script> で閉じない）", …)
must("逃がしても JSON として読める", …)
```

### 実ブラウザの検査（30 件）

```
✓ sitemap の loc が全部絶対 URL  (4 件)
✓ 題名の & と < がそのまま読める（エスケープが正しい）
✓ 下書きが sitemap に出ない / RSS に出ない / 一覧に出ない
✓ 下書きのページ自体が生成されない  (status 404)
✓ すべてのページの title が一意
✓ canonical が全ページ絶対 URL
✓ og:image が全ページ絶対 URL
✓ 記事ページの @type が Article、それ以外は WebSite
✓ 404 ページは検索結果に出さない（noindex）
✓ 本文の 1 行が 45em 以下  (40em)
✓ 見出しが sticky ヘッダに潜らない  (scroll-margin 68px)
✓ 日付が <time datetime> で出ている  (2026-08-01 / 2026年8月1日)
```

アンカーで見出しへ飛んだときの隠れ量は **−78px**（負なのでヘッダの下に出ています）。

**トップページに `description` がありませんでした。**
`index.astro` は `title` だけ渡していて、説明文を書き忘れていました。

## 下書きの漏れを防ぐ仕組み

下書き（`draft: true`）は **一覧・sitemap・RSS の 3 か所すべて**で外す必要があります。
どれか 1 つで漏れても、**書いた本人には違和感がありません**（自分の文章なので）。

そこで絞り込みを `src/lib/posts.ts` の `getPublishedPosts()` 1 つに集約し、
3 か所すべてがそれを呼ぶようにしました。記事ページの `getStaticPaths` も同じ関数を
使うので、**下書きは URL 自体が生成されません**（実測: status 404）。

## 検査対象を sitemap から取るようにしました

Astro サイトのページ一覧を、`verify.mjs` に手で書き並べるのをやめて
**sitemap.xml から取る**ようにしました。

```
（Astro サイトの検査対象: 4 ページ）
```

sitemap は「下書きを外した公開ページの一覧」そのものなので、
ページを足せば自動で端末幅の検査に入ります。カタログのタブで一度やった
「新しい画面が検査から漏れる」を、サイト側でも起こさないための作りです。

取得に失敗したときは**理由を必ず印字**します。黙って 1 ページに落とすと
「全部見たつもり」になるためです。

## 残っている宿題

- **Markdown の中の画像**は、まだ場所を取っていません（`![alt](/x.png)` は
  `width`/`height` を持たないので、読み込みで本文がずれます）。
  記事に画像を入れる前に解決が要ります。rehype で寸法を足すか、MDX にして
  `<Frame>` を使えるようにするかの判断が要ります
- 404 の見た目は静的ホスティング側の設定に依存します（`404.html` を置いても
  ステータスを 404 にしない環境があります）
- ランディング / 会社サイトの雛型は v0.7 後半
