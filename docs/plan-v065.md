## 何を判定にして、何を判定にしないか

ここが一番大事です。**厳しすぎる判定は、無関係な変更で落ちて無視されるようになります。**
前回 WCAG のインライン例外で「直しようのない指摘」を外したのと同じ話です。

| | 例 | 扱い |
|---|---|---|
| **壊れたら困る性質** | タップ領域が 24px 以上 / `role` が正しい / Esc でフォーカスが戻る / 送信された値の形 | **判定にする** |
| **トークンから決まる値** | `space-md` の gap が 16px / prose の幅が 40em | **判定にする**（決定的なので） |
| **配置で変わる値** | 要素の絶対座標 1726px / 画面内の位置 | 判定にしない。「動いた / 動かない」を判定にする |
| **参考として見たい値** | 送信された JSON の中身そのもの | `log()` のまま残す |

**座標そのものを判定にしてはいけません。** フォントの太さが変わっただけで落ちます。
判定するのは「関係」（前より下がっていないか、片方だけ動いたか）です。

## 仕組み

`_browser.mjs` に 2 つ足すだけにします。増やしすぎると書くのが億劫になります。

```js
must("タップ領域が 24px 以上", size >= 24, `${size}px`);
mustEq("gap", gap, "16px");
```

- 通れば `✓` を出して先へ進む（いまの読みやすさは残す）
- 落ちても**その場で止めず**、最後にまとめて報告する
  （1 個目で止まると、残りが直ったかどうか分からないため）
- `finish()` が「判定 N 件中 M 件失敗」を出して終了コード 1

`log()` は残します。判定に向かない値を見るためです。

## 進め方（慎重に、1 ファイルずつ）

**製品のコードには一切触れません。** 触るのは `scripts/` の下だけです。
これは今回いちばん大事な性質で、「検査を直したつもりが部品を壊した」を避けます。

1. `_browser.mjs` に `must` / `mustEq` を足す
2. `verify-states.mjs` を変換 → 単体で走らせて緑を確認
3. `verify-layout.mjs` → 確認
4. `verify-parts.mjs` → 確認
5. `verify-forms.mjs` → 確認
6. `verify-nav.mjs` → 確認
7. `audit-stress.mjs` → 確認
8. **わざと壊して、本当に落ちるか確かめる**（下記）
9. `pnpm verify` 全体

### 8 が要です

判定を足しただけでは「本当に落ちるか」は分かりません。
**部品を一時的に壊して、赤くなることを確かめます。**

- `NavLink` の `min-h-11` を消す → タップ領域の判定が落ちるか
- `Tabs` の `tabIndex` を全部 0 にする → roving tabindex の判定が落ちるか
- `formDataToObject` を `Object.fromEntries` に戻す → 複数値の判定が落ちるか

落ちることを確かめたら、必ず元に戻します。

## ついでに直す: Windows の 3 か所

**実機で確かめられないので、直しても「確認済み」とは書きません。**
README とコードに「要確認」と残します。

| 場所 | いま | 直し方 |
|---|---|---|
| `verify.mjs` の `spawn("pnpm")` | Windows では実体が `pnpm.cmd` で ENOENT | `process.platform === "win32" ? "pnpm.cmd" : "pnpm"` |
| `verify.mjs` の `process.kill(-p.pid)` | 負の PID はプロセスグループ。Windows に無い | Windows では `taskkill /pid /T /F`、POSIX は今のまま |
| `pack.mjs` の `tar` | Windows 10+ には `tar.exe` があるので概ね動く | そのまま。README に注記 |

`verify-install.mjs` は `process.execPath` + `path.join` で tsc を呼んでいて、
**これが正しい書き方**です。他もこれに寄せます。
