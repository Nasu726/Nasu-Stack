## 直したこと

### 段組を畳んだときの向き（配布物）

`Columns` は畳むと `flex-col` になりますが、`alignY`（`items-start`）が
そのまま残っていました。**列方向では `items-*` は横方向の指定**なので、
幅を持たない列が中身の幅まで縮みます。

`alignY` を**横並びになる幅でだけ**当てるようにしました。

**最初に思いついた直し方は間違いでした。** `.wt-col{width:100%}` を当てたら
行方向が壊れ、`auto` の列が 0px になりました（当てて測って気づきました）。

実測: 760px で `auto` の列が **179px → 678px**。1440px は今までどおり（1/3 = 314px）。

### ホイールの向き（配布物）

v0.9c で入れた「縦→横」の変換を**削除**し、**横の動きだけ**を見るようにしました。
コード例や表の上を通っただけでページの縦読みが止まるのが、作者の指摘どおり
害のほうが大きいためです。

`Scrollable` の `axis="x"` から `overflow-y-hidden` も外し、
`Inline wrap={false}`（`wt-nowrap`）と同じ形に揃えました。

判定も入れ替えました。**縦で動かないことも確かめます。**

```
✓ ホイールの横で横スクロールできる  ({"横":120,"縦":0})
✓ ホイールの縦では横に動かない      ({"横":120,"縦":0})
```

### スクロールバーを隠せるように（配布物）

`Scrollable scrollbar="hidden"`。**端の影は残します**——消すと、そこが
スクロールできることを示すものが 1 つも無くなります。
カタログの `Scrollable` の節で切り替えて試せます。

### テーマの保存先（配布物）

`localStorage` は origin 単位なので、`/catalog/` と `/demo/` が同じ入れ物を
共有していました。**利用者が `/app/` と `/docs/` を同じドメインに置いても
同じことが起きます。**

- `ThemeProvider` に `storageKey` と `lockTheme`
- `makeThemeInitScript({ storageKey, lockTheme })`
- `ThemeSwitcher themes={false}` で明暗だけ

デモは**明暗だけ**にしました（作者の判断）。`data-theme` はページが決めた値の
ままです。実測: カタログを vivid+dark にしても `/demo/lp/` は `warm` のまま。

**`client:idle` は使えませんでした。** `requestIdleCallback` はタブが見えて
いないと発火しないので、開いた直後に押しても何も起きないことがあります
（実測で踏みました）。押される場所なので `client:load` にしています。

### カタログのヘッダ（後退の修正）

v0.9c で `max-w-[min(38rem,60vw)]` を `min-w-0 flex-1` に変えました。
半画面は直りましたが、**375px でタブが 13px に潰れました。**

`1024px` 未満は 2 段（ブランド＋トンマナ／タブ）にしました。根拠は実測です。

```
1440px: 器 1024 に対して ブランド 108 + タブ 531 + トンマナ 248 + 明暗 64 = 951
        余り 73px。器が 980 を切ると 1 行には入りません。
```

実測: 375px でタブの可視幅 **13px → 343px**（1 項目 76px）。760px では 728px で
スクロールすら不要。狭いときのヘッダの高さは、余白を詰めて 171px → 155px。

### その他

- ハンバーガーの枠から `overflow-hidden` を外しました（角丸は残ります）
- `dividers` の例が `space="md"` 固定だったので、上のボタンに繋ぎました
  （**部品は正しく、デモが間違っていました**）
- `withBase` の説明に `<img src>` / `<iframe src>` / `fetch` を足しました

## 潰れの検査（指摘 7 への答え）

**これまでの検査は「外へ出ていないか」しか見ていませんでした。**
中へ潰れているものは全部緑のまま通ります。実際、タブの 13px も
`auto` 列の 48px も、Frame の 24px も、1 つも赤くなりませんでした。

`check-responsive.mjs` に**潰れの判定**を足しました。

- 縦に積まれた親の中で、**親の幅の 40% 未満**になっている `.wt-col` / `.wt-frame`
- **スクロールできる器が 1 項目より狭い**もの

これで「全部の部品を 1 つずつ実測する」が、一度きりではなく毎回になります。

### わざと壊して確かめました

```
Columns の畳み方を戻すと → ✗ 場所があるのに潰れている要素: 1 件
                              ↳ <div class="wt-col"> が 48px（親は 238px）
器を 13px にすると        → ✗ tablist（1 項目 76px より狭い）
```

タブ側は、v0.9c の形に戻しただけでは再現しませんでした（新しい枠が
折り返しで逃げるため）。**器の幅を直接 13px にして、判定が鳴ることを確かめて
います**——「戻したら赤くなった」ではないので、そこは正直に書いておきます。

## 追加の 2 件（公開後の指摘）

### 広い画面で本文が左に寄る

1920px で実測すると、器 1024 に対して**導入の本文が 1017 で止まり、
右に 431px の空白**が残っていました。

器を狭めれば揃いますが、**そうするとヘッダが 1 行に入りません**
（ブランド + タブ + トンマナで 951px 必要）。
本文の 1 行は和文 45em までなので、14px なら 630px が上限です
（`check-responsive.mjs` が実際に測っています）。
**器 1024・本文 630 では、縦に積む限り必ず余ります。**

そこで導入部を、1024px 以上で**見出しと本文の横並び**にしました。
実測: 本文の右端 1017 → 1449（器の右端と一致）。

#### 判定が無かったのが原因です

生成物には「広い画面で見出しと本文の幅が揃っているか」の判定がありました
（`verify-create` の 13）。**カタログには無かったので、そこだけ寄ったまま
公開していました。**

`verify-layout.mjs` に足しました。**最初に書いた形は甘すぎました**——
「どこかの段落が右端まで届いていればよい」にしたところ、パネルの中のデモの
段落が偶然 1233px まで届いていて、導入が寄ったままでも緑になりました。
**導入の最初の段落**だけを見る形に直し、わざと戻して赤くなることを確認しています。

```
✗ 9. 広い画面（1920px）で本文が器の右端まで届く
     (器の右端=1449 本文の右端=1017 余り=432)
```

### `width="1/3"` が半画面で効かない

**部品は正しく動いていました。** 768px 未満では縦に畳むのが既定で、
畳んでいる間は幅の指定が効きません（1/3 のまま縦に並べても読みにくいだけです）。

ただし画面には `width="1/3"` と書いてあるのに全幅で出るので、
**不具合に見えます。** デモの側を直しました。

- `collapseBelow` を `tablet` / `desktop` / `null` で切り替えられるように
- **いま縦積みなのか横並びなのかを画面に出す**

実測（700px）: 既定では 619/619（縦積み）、`null` にすると 206/396。
**畳まなければ 1/3 はちゃんと効きます。**

#### この表示は JS で作っていません

要素を測る案を 2 つ試して、どちらも古い表示が残りました。

| 試したもの | 何が起きたか |
|---|---|
| `ResizeObserver` | 描画が止まっているタブでは発火しません |
| `matchMedia` の `change` | 同上。`resize` を足しても飛んできませんでした |

畳む条件は部品と同じメディアクエリなので、**同じ仕組み（CSS）で出し分ければ
ずれようがありません。** `<details>` を使うのと同じ考え方です。

### フッタのリンクの列が縦に折り返す

デモのトップで、「サイト」と「その他」が縦に積まれ、左に大きな空白が
残っていました。

**縮むのがリンクの側になっていたのが原因です。** 説明文は
`max-w-prose` まで伸びるので、残りが足りなくなるとリンクの列が折り返します。

```
器 704 ／ 説明文 468 ／ リンク側に残ったのは 164
56px + 64px(gap) + 75px = 195 > 164 → 折り返し
```

リンクの列を `shrink-0` にして、**折り返すのは説明文の側**にしました。
説明文は何行になっても読めますが、リンクの列は縦に割れると
「まとまり」が見えなくなります。列の間隔も `gap-xl`（64px）から
`gap-lg`（24px）へ。実測: 1280px でも 375px でも同じ行に並びます。

#### ここでも、見ていたページが足りませんでした

判定を足したあと、わざと戻しても**緑のまま**でした。
`verify-seo.mjs` が見ていたのは `/lp/` `/about/` `/contact/` の 3 つで、
**指摘されたトップ（`/`）が入っていませんでした。**

フッタの器の幅はページごとに違います（トップは `narrow`、lp と contact は
`content`）。**狭いほうでだけ折り返していたので、広いほうしか見ていない
判定は永久に鳴りません。** `/` を足して、赤くなることを確認しました。

```
✗ / フッタのリンクの列が横に並んでいる  (サイト=56px@1434 その他=75px@1626)
✓ /lp/ フッタのリンクの列が横に並んでいる  (サイト=56px@1800 その他=75px@1800)
```
