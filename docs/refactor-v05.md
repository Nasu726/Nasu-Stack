# v0.5 後のリファクタリング記録

バグを直しているうちに、**バグを見つける仕組みのほうに穴が開いていた**ことが
分かりました。ここはその記録です。同じ穴を二度開けないためのものです。

---

## 1. 検査していたつもりで、検査していなかった

`pnpm check`（端末幅の検査）はカタログの URL を 1 つだけ渡していました。
ところがカタログは**タブで中身が入れ替わる**画面です。既定タブは「レイアウト」。

つまり **v0.4 と v0.5 で作った部品は、320px で一度も検査されていませんでした。**
「検査は通っている」と思っていた状態が、実際には「検査対象に入っていない」でした。

全タブを直接開いて確かめた結果:

| タブ | はみ出し | タップ<24px | 入力<16px |
|---|---|---|---|
| レイアウト | 0 | 0 | 0 |
| 端末幅 | 0 | 0 | 0 |
| **部品** | 0 | **1** | 0 |
| **入力/選択** | 0 | **16** | 0 |
| 状態 | 0 | 0 | 0 |

### 直したこと

- `App.tsx` に `?tab=` を実装（URL でタブを指定できる）。
  ついでにタブを押すと URL も変わるので、リンクで共有できるようになりました。
- `<div data-active-tab>` を追加。検査スクリプトが
  「開いたつもりが別のタブだった」を黙って見逃さないための目印です。
- `verify.mjs` の検査対象を **5 タブ全部**に変更（1 ページ → 6 ページ）。
- `scripts/_browser.mjs` を新設。各 `verify-*.mjs` が持っていた
  「起動してタブを開く」処理を 1 か所へ。ボタンのクリックではなく URL で
  開くようにしたので、ボタンの文言が変わっても静かに壊れません。

## 2. 検査そのものが間違っていた（誤検知 3 種）

タブを全部見るようにしたら 17 件の指摘が出ましたが、うち多くは検査側の誤りでした。

**(a) sr-only の入力を「小さすぎるボタン」と呼んでいた。**
FileDrop は見た目を `<label>` に差し替え、`<input type=file>` を 1px に隠します。
1px 以下の要素は視覚的なターゲットではないので数えません。

**(b) 包みを見ずに四角だけ測っていた。**
チェックボックスは 20px でも、包む `<label>` が 44px なら押せる範囲は 44px です。
`el.closest("label, button, a[href]")` を辿って**実際の当たり判定**を測るようにしました。

**(c) 横スクロール領域の中の `min-width` を叱っていた。**
表は `Scrollable` の中で `min-width: 672px` を持ちます。これは意図どおりです。
`width` 側には除外があったのに `min-width` 側に無い、という取りこぼしでした。

**(d) URL を「1 行が長すぎる本文」と呼んでいた。**
`https://example.com/very/long/...` は途中で切れない 1 語です。読みやすい行長の話ではなく、
はみ出しの検査の担当。40 文字を超える単語を含む段落は行長の対象から外しました。

## 3. 誤検知を除いて残った、本物の指摘

**(a) 表の中のチェックボックスが 20×20 のまま。**
カード表示のときは `<label>` で包んでいたのに、表のセルでは裸でした。
`BoxLabel` を作り、文字ラベルの有無にかかわらず必ず包むようにしました。

ここで一度失敗しています。最初 `w-full` で広げようとしましたが**効きませんでした**。
表の列幅は中身から決まるので、中身が「親の 100%」と言うと循環して 20px のままです。
`min-w-11`（44px）で下限を与えるのが正解でした。

**(b) 並べ替えボタンが 44×20。**
指で触る端末では `tokens.css` の base 層が 44px まで広げますが、
マウスの端末では文字の高さ（20px）のままでした。`min-h-6`（24px）を明示。

**(c) 楽観更新のデモのチェックボックスが裸だった。**
題名まで含めて `<label>` で包み、行のどこを押しても切り替わるようにしました。

## 4. 配布物の依存が 9 項目で足りていなかった

これは検査の穴としては一番大きいものです。

`registryDependencies` は「この部品を入れるとき一緒に入るもの」の宣言です。
書き忘れても**このリポジトリでは何も起きません**。全ファイルが揃っているからです。
壊れるのは利用者が 1 つだけ入れたときで、しかも手元では再現しません。

```
npx shadcn add @nasu/data-table
→ data-table.tsx は入る
→ その中の import { cn } from "@/lib/utils" は入らない
→ 利用者のところだけビルドが落ちる
```

`verify-install.mjs` は全部まとめて入れて型検査するので、これを見つけられません。

`scripts/check-registry-deps.mjs` を新設し、**ソースが実際に import しているもの**と
宣言を突き合わせるようにしました。その場で 9 項目の漏れが出ました。

| 項目 | 足りなかったもの |
|---|---|
| action-provider / action-button / async-select | `@nasu/action` |
| async-boundary | `@nasu/utils` |
| async-form / data-list / data-table / file-drop | `@nasu/utils`, `@nasu/action` |

`pnpm verify` の 6 番目の工程として常設しました。

## 5. 中断できないつもりの中断（`useOptimisticList`）

```ts
const ctx = (): ActionContext => ({ signal: new AbortController().signal });
```

`AbortSignal` を渡しているので中断できるように見えますが、この controller は
**誰も持っていないので誰も中断できません**。画面から消えたあとも保存が走り続けます。

フック 1 つにつき 1 本の controller を持ち、アンマウントでまとめて中断するように変更。
中断による失敗を利用者に通知しないよう `isUnmountAbort()` で分けています。

開発中の StrictMode は mount → unmount → mount を通すので、
一度中断した controller をそのまま使い回すと**以降の保存が全部中断扱い**になります。
中断済みなら作り直す、を入れてあります。

## 6. 入力欄の見た目が 4 か所にコピーされていた

`Field` / `SelectField` / `DateField` / `AsyncSelect` が同じ class 文字列を持っていました。
とくに `text-base`（16px）は、1 か所でも落とすと **iOS がその欄だけ画面を自動拡大**します。
手動でしか戻せません。

`lib/utils.ts` に `inputClass()` を置いて 1 か所へ。
`async-form` に置かなかったのは、`AsyncSelect` をフォームなしで使いたい人に
フォーム一式を背負わせないためです。

そのほか `ConfirmProvider` の固定 id（`wt-confirm-title`）を `useId` に変更しました。
Provider が 2 つ置かれると id が重複し、読み上げの参照先が狂います。

## 見送ったもの

**デモの `Row` / `ROWS` / `COLUMNS` の共通化。**
一見コピーですが、部品タブは「8 列をカードに組み替える」ため、
入力/選択タブは「14 行をページングして選ぶ」ためのもので、形が違います。
無理に共通化すると、どちらのデモも要点を示せなくなります。
