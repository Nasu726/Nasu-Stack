## Phase 1 — サブパスの穴

`base` が効くのはバンドラが出す資材だけで、**手書きの `href="/…"` は書き換わりません。**

いちばん重いのは、v0.9b で足した判定が `.js` と `.css` しか見ていなかったことです。
**資材はもともと壊れていない部分**なので、壊れていない部分だけを確かめていました。

- `withBase()` を配布物に置き、`SiteHeader` / `SiteFooter` が**自動で付ける**
  （書き忘れても手元では壊れないので、覚えてもらう形にすると必ず漏れます）
- 判定を作り直し、**同じサイト内の参照を全部辿る**ようにした
- **実ブラウザで開いて、飛んだ要求の失敗を拾う**（`works.json` は HTML に出ません）

絶対 URL の出どころが 2 つあり、**同じページに 2 つの違うアドレス**が出ていたのも直しました。

## Phase 1.5 — カタログとデモの中身

作者が公開されたものを実機で見て、13 件の指摘が出ました。
**部品側の検査はその間ずっと全部緑でした。**

### 個人の情報が公開ページに載っていた

案件名・氏名・所在地（市まで）。Phase 1 で `works.json` は差し替えましたが、
**カタログ側に同じものが残っていました。** 報告された 1 か所だけを直して、
同じ性質の場所を探さなかったのが誤りです。

`apps/site` は Phase 2 で 3 つ目の雛型の原本になるので、残っていれば
**利用者全員のサイトへ配られていました。**

### 余白のクラスが、エラーも出さずに 0px になっていた

余白の段階は Tailwind 標準の名前空間を避けているので、使う形ごとに
`@utility` が要ります。定義されていたのは `p-*` `px-*` `py-*` `gap-*` だけでした。

```
死んでいたもの: pt-2xl / pt-3xl / pb-3xl / pb-2xs / mt-xs ×4 / mt-xl / mt-3xl / mb-2xs
```

**配っている `site-footer.tsx` の中にもありました。**
→ `scripts/check-space-utilities.mjs` が `tokens.css` を読んで見張ります。

### 手元の配信サーバが、本番と違っていた

`BASE_PATH` を渡しても `public/` が `/` にも生えていました。
本番の `/` は別のサイトなので、**root を指したリンクが手元でだけ通ります。**
端末プレビューの iframe が出していた 404 は、これで素通りしていました。

## Phase 2 — 3 つ目の雛型（`--template blog`）

ブログ・LP・会社概要・問い合わせ・RSS・sitemap・404 が入った状態から始められます。

中身は `apps/site`（公開しているデモ）から**生成**します。手でコピーして
commit しません。2 か所に置くと「デモは直したが雛型は古いまま」が静かに起きます。

**記事だけは写しません。** `apps/site` の記事は「この記事は検査用です」と
自己申告していて、そのまま配ると利用者全員のブログにその文章が載ります。
漏れは**ファイル名の集合**で見張ります（文面を言葉で探す形も書きましたが、
3 本中 1 本しか拾えませんでした）。

## Phase 3 — エディタの補完

`wt-` と打つとこのテンプレートの部品だけが並びます（astro 22 / blog 23 / vite 29）。
`registry.json` と各部品の型から生成するので、手で書いた場所はありません。

**TypeScript を本当に解析してはいません。** `export interface XxxProps` の
中身を深さ 1 の行だけ読みます。`extends` の先は見ないので、継承した必須の
props は出ません。できないことをできるつもりで書くほうが害が大きいので、
範囲を狭く切ってコメントに残しました。

書いている途中で生成側の欠陥が 3 つ出ました。**どれもエラーになりません。**

| | 何が起きていたか |
|---|---|
| `export function Columns` を先に見つけて止まる | `Column` が「存在しない」判定になり、補完から消えた |
| `=>` の `>` を閉じ括弧として数える | 深さが負になり、その行から後ろの props が全部消えた |
| 必須の真偽値を属性名だけで出す | `<Dialog open />` になり、常に true になっていた |

### P2-15（生成物の lockfile）は同梱しませんでした

同梱したものは、利用者が受け取った時点で既に古いためです。ビルド時に作るには
`npm install` が要り、`pnpm verify` が通信に依存するようになります。

代わりに、**利用者の `npm install` が作ったものを commit してもらう**形に
しました。HowToUse に理由つきで書き、`.gitignore` が弾いていないことを
機械で確かめます。

## Phase 5 — CI

`verify-create` が **PR でも走ります。** それまではマージ後（公開の直前）に
しか走らなかったので、気づくのがマージの後でした。
定義は `verify.yml` の 1 か所で、`pages.yml` は `workflow_call` で呼ぶだけです。

### 公開先を実ブラウザで見る判定が、一度も走っていませんでした

`smoke` は `verify-published.mjs` を呼ぶだけで、**playwright を入れていません
でした。** スクリプトは入っていなければ黙って飛ばすので、HTML に出てこない
URL を拾う判定が公開先に対して一度も動いていませんでした。

`smoke` に Chromium を用意し、**CI では飛ばさず赤くする**ようにしました。
